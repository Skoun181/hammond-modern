# Hammond Modern v1.1.7 – Reifen & Fahrzeugübersicht

## Neu
- Eigene Reifenverwaltung mit Fahrzeugzuordnung, Hersteller/Modell, Größe, DOT, Saison, Reifensatz, Traglast-/Geschwindigkeitsindex, Runflat, Profiltiefe, Druck, Laufleistung, Kaufpreis/-datum, Lagerort, Status und Radposition.
- 1–4 Reifen gleichzeitig anlegen; alle Werte gelten pro Reifen. Einzelne Datensätze bleiben bearbeitbar. Montierte Reifen erhalten unterschiedliche freie Radpositionen. Bei Konflikten wird die gesamte Anlage zurückgerollt.
- Kontrastreiche Reifenansicht in Dark/Light Mode mit deutlich sichtbarem Fahrzeugnamen und Kennzeichen.
- Neue Fahrzeugkacheln mit letztem erfasstem Kilometerstand aus Tankungen oder Ausgaben (Originaleinheit), Kraftstoff, Baujahr, Hubraum, Historie, Reifenstatus, Saison und montierten Größen.
- Eigene Fahrzeugübersicht sowie Fahrerübersicht mit Suche und bedarfsgesteuertem Formular.
- ZIP-Backup, Original-Hammond- und Fuelly-Import unter Backup & Umzug zusammengeführt.

## Backup und Kompatibilität
Reifen und Zuordnungen sind Teil neuer portabler ZIP-Backups. Ältere kompatible Backups ohne Reifentabelle können importiert werden, ersetzen aber auch die Reifenliste. ZIPs mit Reifendaten sind nicht für den Restore in v1.1.6 geeignet. Keine Passwort-Hashes oder Secrets im portablen ZIP.

## Update
Vor dem Update /config, /assets und .env extern sichern. Bestehende Mounts, JWT_SECRET, Netzwerk und IP beibehalten. Die neue Reifentabelle wird beim Start angelegt. Bei einem Downgrade die vor dem Update angelegte kompatible Sicherung verwenden.

Docker Hub: `skoun181/hammond-modern:1.1.7` (linux/amd64), alternativ `latest`.
```bash
docker pull skoun181/hammond-modern:1.1.7
```
Bei Compose Image-Tag anpassen, dann `docker compose pull && docker compose up -d`. Git-Tag: `v1.1.7`.

Der vorangegangene Develop-Stand wurde vom Anwender praktisch getestet. Go-Tests, Vue-Build und GHCR-Starttest waren erfolgreich. Ein vollständiges Sicherheits-Audit bleibt offen.
